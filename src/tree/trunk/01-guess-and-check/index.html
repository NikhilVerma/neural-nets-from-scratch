Guess and check

The problem that brought us here

We're thinking of a rule that turns one number into another. We give the machine examples. Can it find the rule?

We picked a rule and kept it to ourselves. Then we fed it sixty numbers and wrote down what came out the other side. Those sixty pairs are everything the machine gets. It never sees the rule.

The machine is about as simple as a machine can be. It has two knobs. It takes the number you give it, multiplies by whatever the first knob says, then adds whatever the second knob says. That's the whole machine. Set the knobs to the right pair of numbers and it copies our secret rule exactly; set them wrong and it talks nonsense.

So the question "can it find the rule?" turns into something much more concrete: can it find the right two numbers?

The simplest thing that could work

Set both knobs to random numbers. See how that did. Do it again. Keep whichever setting did best, and throw the rest away. That's it — there is no cleverness in here at all.

Except we just smuggled in a word that has no meaning yet: best. The machine can't compare two guesses until we tell it what makes one guess better than another. This is the first thing this whole subject forces us to invent, and it goes like this.

Take one example. Run its input through the machine. Compare what came out with what should have come out — that gap is the mistake on that example. Now square it. Squaring does two useful jobs at once: it makes every mistake positive, so being too high can't cancel out being too low, and it punishes big misses far more than small ones. Being off by 4 is not twice as bad as being off by 2; it's four times as bad. Finally, average the squared mistakes across all sixty examples. That average is the guess's score. Zero means perfect. Lower is better, always.

The other thing we need is a source of random numbers we can replay. We write our own in five lines: give it a starting seed and it produces the same stream of numbers every time. That matters more than it sounds. Every claim in these lessons is "this method beat that one" — and if each run rolled different luck, you could never tell whether the method helped or the dice did.

Watch it learn

Sixty examples, plotted. Grey is the guess the machine just made; green is the best setting it has found so far. Press the buttons and watch green creep toward the cloud.

Watch it break

Leave auto-guess running and the third readout is the one to watch. For the first few guesses the record keeps falling. Then it holds for ten guesses, then a hundred, then thousands. The machine is not getting worse at guessing — it is doing exactly the same thing at exactly the same speed. What changed is the size of the target. Once you're close, only a tiny patch of settings is any better than where you already stand, and rolling dice into a tiny patch takes a very long time.

Read that list of guess numbers again, because it is the whole problem in one line. The gaps between improvements don't grow steadily. They multiply. A handful of records in the first hundred guesses, one somewhere in the first thousand, one somewhere in the first ten thousand — and then a run of thousands of guesses that buy nothing at all.

The staircase shows the same thing as a picture: a cliff, then flat. Not flat because we've arrived — the line on the scatter plot is still visibly not the answer — but flat because every further step down now costs about ten times what the last one cost. Random guessing doesn't converge on a rule. It buys lottery tickets, and the tickets keep getting more expensive.

And notice what we are throwing away. Every guess produces a score, and we look at that score exactly once, to answer "record or not?", and then bin it. Two guesses that both lost still told us something: one of them lost by less. We never use that.

What engineers call this
parameters
The knobs — the numbers the machine is allowed to change while it learns.
loss
The score. Confusingly, a high loss is bad; the goal is always to make it small.
mean squared error (MSE)
Our exact recipe for the score: square every mistake, then take the average.
random search
The strategy on this page — sample settings at random and keep the best one seen.
seeded pseudo-random generator
Our five-line dice roller. Same seed, same numbers, so an experiment can be re-run exactly — what people mean by a reproducible result.
